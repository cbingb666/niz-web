# 校准工具落地方案

[English](calibration-implementation-plan.md) · **简体中文**

方案日期：2026-09-28；更新：2026-09-30。第 1–3 批已实现，并按用户要求在开发环境和生产构建中默认提供，第 4 批实机资格验证仍待完成。命令依据和原厂文件哈希见[校准调研](calibration-research.zh-CN.md)，当前使用方式见[贡献指南](../CONTRIBUTING.zh-CN.md#校准开发)，实际验证结果记录在 [VALIDATION.md](../VALIDATION.md)。下文描述当前实施设计和验收条件。

## 首版交付范围

为以下精确的 ATOM66 组合提供三步校准工具：`66EC-S`、VID/PID `0483:522A`、固件 `66EC(S);V1.4.4;V1.0;`；以及 `66EC-XRGB`、VID/PID `0483:502A`、固件 `66EC(XRGB)BLe;V1.2.5;V1.0;`。两者均默认可用，实际硬件行为仍待验证。RGB 组合于 2026-09-30 根据用户截图中的身份补入，沿用相同的原厂校准客户端静态证据，不代表已通过实机验证其固件兼容性。

功能为释放校准、按需执行一组或多组按住校准、解锁后人工试键。经描述符验证后使用现有配置接口。在设备卡片增加次要操作「校准按键」，继续突出主要操作「配置设备」。打开校准不发送命令、不读取配置、不切换当前编辑器；校准无需先载入键位配置。

界面和 HID 会话共用一份能力判断：精确型号、VID/PID、完整固件和报告描述符。已配置的组合在开发环境和生产构建中均无需开关即可使用；证据状态单独记录，仍未通过实机验证。不支持的固件显示简短原因，不提供可执行校准按钮。测试虚构型号不加入生产注册表。

首版范围不含校准备份/恢复、毫米键程、实时电容、每键成功状态、固件升级、其他型号或 WebMCP 校准动作，现有协议证据不足以支持这些功能。开发、验证和构建遵循[项目约定](../AGENTS.md)，仅在本地进行。

## 用户流程与文案

| 步骤 | 用户任务及操作 | 硬件行为 |
| --- | --- | --- |
| 1. 释放全部按键 | 「请松开所有按键。校准期间键盘无法输入，请用鼠标或触控板操作。」主按钮「开始校准」，次按钮「取消」且默认聚焦。另用一句话说明配置备份不能恢复校准。 | 用户确认且松开启动用键后，重新核对固件和描述符；发送 `00 D9 00`、`00 DB 00`，等待 `DA`。 |
| 2. 按住异常按键 | 「按住需要校准的键，完成后再松开。」主按钮「校准按住的键」。等待时保持「请保持按住」。完成后可再校准一组，或「结束并解锁」。 | 每次明确操作发送一次 `00 DD 00`，等待 `DE`。命令不携带键号或掩码。释放校准完成后允许直接结束，无需强制执行按下校准。 |
| 3. 测试键盘 | 解锁报文发送后，提供带焦点的小型本地试键区和「完成」，请用户检查异常键。 | 发送一次 `00 D9 01`。区分校准完成通知、解锁发送成功和用户实际观察到的输入。 |

上述前缀属于 64 字节数据区，其余补零，Report ID `0` 单独传入；依据及回复限制见调研文档。

**不能在用于确认的按键仍被按住时校准。** Enter/Space 激活开始按钮时，阻止立即发送并保持焦点，等对应 `keyup` 后再启动。只在对话框内跟踪该次交互，不监听全局输入；长按重复 keydown 不得重复启动。丢失 keyup 时保持待启动，提供鼠标继续或取消，不用定时器代替松开。用户仍需自行松开全部物理键：DOM 事件不能区分是哪把键盘产生，也不能证明所有键都已释放。除 jsdom 外，还需在真实浏览器验证。

复用 AlertDialog、Button、主题令牌及静态锁键示意。每步只呈现一个任务，短文案左对齐，焦点清晰，点击区域充足，布局变化不清空内容。校准不显示传输百分比，以阶段文字表示进展，仅在收到完成通知后推进。

整个校准会话保持背景 inert 和向导内焦点限制，包括等待用户按住按键的阶段；向导自身操作保持可用。命令执行中不能用 Escape 或背景点击关闭。已完成阶段之间通过「结束并解锁」退出；返回不得重发释放校准，也不暗示回滚。失败后解除页面锁，保留可操作错误，并在相关设备卡片保留未解决的硬件状态提示。

试键区只做本地人工检查。普通 DOM 输入无法证明来源设备、Fn 校准、完整物理键覆盖或传感器精度，输入文字不进入诊断，也不上传。

## 运行状态

首版一次只允许一个校准会话，沿用应用的全局操作锁；连接资料和结果仍归属指定设备。界面步骤与内部执行阶段分开：

| 阶段 | 允许的推进 |
| --- | --- |
| `preparing` | 取消不产生校准通信；确认并松开启动用键后开始 |
| `identifying` | 核对捕获的目标、固件、描述符；不符时在锁键前失败 |
| `locking` | 发送前先记录「可能已锁键」；发送已结束后进入释放校准 |
| `calibrating-release` | 只有有效的预期 `DA` 才进入等待按住阶段 |
| `awaiting-held-keys` | 接受一次按下校准请求或结束；等待用户时继续保持独占 |
| `calibrating-press` | 只有有效的预期 `DE` 才回到等待按住阶段 |
| `unlocking` | 执行一次有时限的清理尝试，最终必须结束会话 |
| `testing` / `failed` | 释放硬件独占，保留结果或可操作错误 |

弹出确认前取得一个不透明的目标标识，其内部绑定设备 ID、`ConfigDevice` 对象、连接世代、型号和固件。进入独占操作后、首条命令前再核对。给界面回调分配本地 run ID；它不是固件事务编号，不能用于证明迟到报文属于哪次硬件操作。

结果分别保存：释放阶段是否完成、收到确认的按下批次数、解锁状态（`not-needed`、`sent`、`failed`、`unknown`）及失败原因。没有解锁确认不能写成 `unlocked: true`，批次数也不等于校准成功键数。

未解决结果独立于载入配置保存，包含页面内设备 ID、名称和固件。即使设备从未创建编辑器，在关闭失败连接后也要保留恢复入口。不能仅凭相同 VID/PID 把旧结果关联到另一把键盘；页面内编号不是硬件序列号。

`DB`、`DD` 不自动重试。错误回复、超时、断线或目标变化都结束当前运行并进入清理。请求没有事务编号，因此同码迟到回复不一定能与新操作回复区分；超时后终止会话，不能立即在不确定的旧报文流上重开校准。实机出现异常重复时暂不开启支持，不能放宽解码器来掩盖。

每次校准回复暂用可注入的 10 秒截止时间，发送保留现有 5 秒时限。它们是临时失败边界，不是实测耗时或完成倒计时，之后依据实机抓包调整。任何超时都不推进到成功。阶段之间等待用户操作时，不自动执行校准或结束。

## 模块与接口

用一个小接口的校准模块集中处理复杂行为：调用方只选择用户动作，命令顺序、回复和清理由模块内部负责。沿用现有 `ConfigDevice` seam，以及真实设备/FakeDevice adapter。

| 文件 | 职责与产物 |
| --- | --- |
| 新增 `src/calibration.ts` | 独立于框架的阶段、报文构造/解码、有界等待、结果类型和用户动作，不依赖编辑器、备份库或 DOM。 |
| [src/hid.ts](../src/hid.ts) | 从 `connections` 解析目标，管理独占和生命周期，复核身份、接收报文、跟踪实际发送结束，并执行受限的最终解锁。 |
| [src/devices/model.ts](../src/devices/model.ts)、[atom66/model.ts](../src/devices/atom66/model.ts) | 定义精确组合与证据状态，可用性为 available/unsupported。普通 `66EC` 型号匹配仍不足以开放此功能。 |
| [src/store/app-store.ts](../src/store/app-store.ts) | 保存向导快照、每设备结果和消息标识；提供打开、开始、校准按住键、结束、关闭结果动作。 |
| 新增 `src/components/calibration-dialog.tsx`；[device-manager.tsx](../src/components/device-manager.tsx)、[app-dialogs.tsx](../src/components/app-dialogs.tsx)、[src/app.tsx](../src/app.tsx) | 设备入口、三步向导、操作渲染、焦点/inert，以及存在校准会话时的离页提醒。 |
| [src/i18n/en.ts](../src/i18n/en.ts)、[zh-CN.ts](../src/i18n/zh-CN.ts) | 同步文案与插值；错误和活动记录保存消息标识。 |

已实现的会话接口：

```ts
// 同步准备目标，不产生 I/O。
const target = session.calibrationTarget(deviceId);

// 用户确认且松开启动用键后调用，返回归属当前会话的操作对象。
const run = session.beginCalibration(target, onUpdate);
await run.calibrateHeldKeys(); // 只在已完成阶段之间有效
await run.finish();            // 一次解锁；重复结束共享原结果
await run.done;                // 结束、失败、断线和停止应用时都必须结束等待
```

`beginCalibration`执行本次授权的身份核对、锁键和释放校准。向导仅在释放完成后启用按下校准，模块内部也独立校验同一条件。React 不获得任意发送命令码的接口。

**不要调用 `selectDevice` 来校准设备卡片。** 当前 store 会据此激活另一个编辑器。应直接取得私有连接记录并贯穿本次会话使用。编辑 A 时校准 B，A 仍是当前编辑器，两台的编辑都保留。

一个 `HIDSession.exclusive` 操作覆盖完整会话，包括等待用户操作。按下/结束动作向已经运行的操作传递信号，不再排入另一个 exclusive，否则会死锁。校准占用时，新的读取、写入、USB 授权直接拒绝，不能暗中排队到校准后再执行。自动恢复连接只做现有身份识别，不重启校准。

其他动作继续遵守 `isLocked`，校准向导自身则按阶段判断允许动作。操作类型加入 `calibrate`，先渲染校准向导，再处理既有读写遮罩。离页提醒条件从未保存编辑扩为「未保存编辑或存在校准会话」；它只是提醒，不是解锁机制。

## 结束与异常清理

当前 [PacketChannel.send](../src/hid.ts)用定时器与 `sendReport()` 竞争，超时后通道永久失败。需在内部另外跟踪底层发送 Promise 是否真的结束。清除定时器不等于取消设备传输。

只有当前校准会话的清理路径可尝试最终解锁：限定原设备对象/世代、连接仍打开、没有未结束的前序发送，只允许固定解锁报文，每次运行最多一次，且不能让失败通道恢复普通通信。接收或协议错误使通道失败、但发送已经结束且仍可用时，该清理仍应可执行。不要给界面暴露通用的绕过错误发送方法。

| 结束情况 | 处理方式 |
| --- | --- |
| 开始前取消，或锁键前身份检查失败 | 无需解锁，不发送校准命令 |
| 正常结束 | 尝试一次解锁；发送成功记为 `sent`，再让用户试键 |
| 可能已锁键后发生错误回复、接收超时或已结束的发送拒绝 | 原设备/世代仍连接且无未完成发送时，尝试一次最终解锁；即使清理成功也保留原始失败 |
| 发送超时，底层发送仍未结束 | 不并发发送解锁，不自动重开；记录 `unknown`，结束会话并停用该配置连接 |
| 目标拔线或连接世代变化 | 及时结束，不向替代连接发命令，保留错误和各设备编辑 |
| 解锁自身失败或超时 | 不重试，记录 `failed` 或 `unknown`，停用该配置连接，提供经过实测的人工恢复步骤 |
| 应用正常停止 | 中止等待用户的状态；关闭句柄前完成符合条件且有时限的清理，使 `run.done` 结束；不能排在自己的 exclusive 后面等待 |

协议或传输失败后，不把不确定的报文流交回普通配置操作。关闭该通道，只失效它的硬件读取基线，并要求用户主动重新连接这台设备；在此之前暂停该失败连接的自动恢复。其他设备的已有连接和编辑继续保留。

强制关闭标签页或崩溃无法保证异步清理。目标实机的人工恢复步骤仍是硬件资格验证的必要内容；在完成之前，提示应说明状态不确定并引导原厂支持，不能承诺重新插线一定解除锁键。「再试一次校准」不能代替恢复。

## 配置、诊断与兼容

校准不读取或重载键位配置、不清空草稿、不消耗撤销历史，保留 `Profile`、JSON/`.pro` 和 IndexedDB 兼容格式。配置备份不是校准快照。配置写入仍完整执行「基线检查 → 检查外部改动 → 备份 → 写入 → 回读」。

发出会改变校准的命令后，使目标设备的硬件写入基线失效，但保留载入配置和草稿。以后写入需按现有流程主动重读/导入。实机确认正常校准不改变配置数据后，未来可调整策略，在干净完成时保留基线；失败或不确定始终使基线失效。目标不是当前编辑设备时，也必须只修改目标记录。

保留可选的诊断记录，只涵盖本次校准：设备/固件/描述符、递增序号和相对时间、方向、Report ID、完整报文字节、阶段及发送/超时结果。最多保留 256 条报文并标记截断；区分发送尝试和发送成功。用户主动导出到本地，使用独立 `niz-calibration-capture` 标识，不挪用 `atom66-read-capture`，不记录试键文字，不上传。私人抓包放在 Git 和构建产物之外。浏览器记录不能代替原厂工具的 USB 抓包。

运行中等待用户操作时，测试应等待阶段状态，不能调用现有 `settle(session)`；该工具等待 `session.tail`，会一直等到整笔校准结束。

每批运行相关测试，代码交付前执行 `npm run check`。实际浏览器检查中英文、窄屏及 1280 × 800 布局；jsdom 不等于浏览器验收。保留独立 HTML、脚本哈希 CSP 和 `connect-src 'none'`。实现改变行为时同步中英文使用/架构文档，在 `VALIDATION.md` 记录真实硬件结果与未验证项。

第 1–3 批已在本地使用模拟设备完成实现。第 4 批仍需明确获准的真实硬件操作和可用设备，不代表已验证真实校准、持久化或恢复。实现不构成固件变更、推送 main 或部署授权。
