# 架构与兼容性

[English](architecture.md) · **简体中文**

[返回贡献指南](../CONTRIBUTING.zh-CN.md) · [Agent 工作约定](../AGENTS.md)

NIZ Web 是纯浏览器应用，通过 WebHID 访问键盘的 USB 配置接口。没有本地设备代理、后端服务或云端配置存储。当前协议实现来自原版 DLL、已有原生移植及真实读取样本；网页实机验收仍未完成。

## 模块入口

| 位置 | 职责 |
| --- | --- |
| `src/main.tsx`、`src/app.tsx` | 应用入口、HID 会话生命周期与页面组合 |
| `src/components/` | React 界面；`ui/` 为本地 shadcn/ui 基础组件 |
| `src/store/` | Zustand 状态、操作、设备事件与 React 订阅 |
| `src/editor.ts` | 独立于 React 的编辑模型、差异和撤销历史 |
| `src/hid.ts` | 设备通信、连接状态、读取基线与写入保护 |
| `src/protocol.ts` | NIZ EC 报文解析、型号归属及配置转换 |
| `src/devices/` | 型号定义与识别注册表；`atom66/` 包含布局与 `.pro` 转换 |
| `src/storage.ts` | IndexedDB 事务备份 |
| `src/model-tools.ts` | 可选 WebMCP 页面工具 |
| `src/i18n/` | 中英文文案、按键名称、键帽缩写与语言偏好 |
| `src/lib/`、`src/types/` | 浏览器环境、下载、布局测量及 WebHID 类型 |
| `scripts/` | 单文件构建插件与项目外读取样本回放 |
| `tests/` | 协议、状态、React 交互与构建产物测试 |
| `drivers/` | 按型号保存的原厂软件，仅供参考，不参与构建 |

项目根目录是唯一在用的 Web 源码入口。包名、构建插件和测试环境使用 `niz-web`；下面列出的旧名称是兼容标识。

## 型号识别与配置归属

`src/devices/atom66/model.ts` 集中维护 USB 筛选条件、固件识别、物理布局、编辑层、配置组数、Fn 规则、计数 / RGB 能力及演示内容。

`src/devices/model.ts` 定义接口，并从布局和层数推导键数与可编辑记录范围。`src/devices/index.ts` 是生产型号的唯一注册入口，目前只注册 ATOM66。

连接时先筛选 USB 配置接口，再读取固件，在候选型号中唯一匹配。未知或匹配多个型号时，不继续读取按键配置。同一个 USB ID 不代表同一型号，也不能按报文数量猜测型号。

`HIDSession` 保存设备型号，`Profile` 保存配置型号。编辑器、布局、方向键导航、确认摘要和页面工具均使用配置的型号信息；未载入配置时默认显示 ATOM66。

导入合并、配置比较和硬件写入均检查型号一致性。即使固件字符串和记录数量相同，也不能混用不同型号的配置。

### 扩展型号

1. 从官方资料与真实只读样本确认 USB 标识、固件识别、按键顺序、布局、配置组数和能力。
2. 确认共用 NIZ EC 报文及命令格式后，在 `src/devices/<型号>/model.ts` 定义型号，并加入 `supportedModels`。计数与 RGB 长度、记录寻址、编辑范围和 Fn 同步应从型号定义取得。
3. 如果命令、报文结构或键码含义不同，先实现协议与转换，再扩展协议选择。`protocol: 'niz-ec'` 只声明已实现的协议，添加参数不等于支持新协议。
4. 增加真实样本的报文往返与设备行为验证，再声明支持。

`tests/model-fixtures.ts` 中的 68 键 / 2 层 / 4 组型号是未注册的虚构测试设备，只用于检查结构可扩展性。

## 兼容格式

| 内容 | 保留的格式或标识 |
| --- | --- |
| ATOM66 JSON | `format: 'atom66-macos'`；旧导入文件与备份明确归属 ATOM66 |
| 新型号 JSON | `format: 'niz-web'`、`schema: 1`，必填 `model` 型号 ID |
| ATOM66 读取诊断 | `atom66-read-capture` |
| 新型号读取诊断 | `niz-read-capture`，携带 `model` |
| 浏览器备份数据库 | `atom66-web-backups` |
| 语言偏好 | `atom66.locale` |
| 页面工具 | `atom66_read_status`、`atom66_read_keys`、`atom66_stage_key_edits` |

Windows `.pro` 只支持 `src/devices/atom66/legacy.ts` 中明确识别的 ATOM66 格式。JSON 导入与设备写入检查固件一致性，不直接跨版本写入。

ATOM66 支持完整三组或九组配置。V1.4.4 九组共 594 条记录，界面只编辑前三组；其余六组保留原始报文，写后校验逐字节比较扩展组。三组文件合并到已读取的九组配置时，使用设备原有扩展组，不将其清空。

## 设备、编辑与写入

`HIDSession` 由应用入口管理生命周期，React StrictMode 不会重新创建连接。Zustand 通过设备事件同步视图，组件切换不会触发硬件写入。

连接通道、型号、读取基线与连接世代按设备隔离。每台设备也有独立的编辑器、草稿、选键及撤销历史。新增连接不会切换工作台，旧确认不能用于新连接。

连接只识别设备。用户从「配置设备」或「重新读取配置」发起读取并确认后，才读取配置。取消或失败不会自动重复读取。

写入流程依次为：校验配置归属与基线、再读设备检查外部改动、完成备份事务、发送配置、回读比较。一次用户确认覆盖整个流程。写入不是设备级原子事务，中断可能造成部分写入，不自动重试或回滚。

编辑模型保留最多 50 笔已应用操作，包含 Fn 联动、批量改键与 RGB。载入新配置或写入成功后清空历史；未应用输入按层和键位保留，不进入已应用操作的历史。

### 进度语义

| 阶段 | 进度依据 |
| --- | --- |
| 发送按键配置 | 成功发送包数 / 本次总包数，包含宏续包 |
| RGB 与按键计数 | 实际收发字节数 / 当前型号所需字节数 |
| 回读 | 已接收包数 / 待校验配置包数；超出目标数量时不再显示比例 |
| 初次读取与写前检查 | 未知总包数，只显示阶段状态与等待指示 |
| 本地备份、设备处理等待、结果校验 | 无传输比例，只显示阶段状态与等待指示 |

实际收发量由底层进度事件记录，界面不显示步骤编号或数据包明细。发送阻塞或失败时完成量不增长；页面锁定持续到整笔事务成功或失败。

## 界面实现

- 主题令牌位于 `src/styles.css`，`components.json` 配置 `@/` 别名。弹窗复用现有 Dialog / AlertDialog 的尺寸、圆角、间距和按钮。
- 设备管理、连接引导与工作台共用设备命名：优先设备名称，仅重名时附加本页面编号。编号不作为跨页面身份。
- 顶栏提供品牌、面包屑、语言、帮助与 GitHub 链接。底栏集中放置设备状态、配置工具、撤销、重做和写入；页面按底栏实际高度预留空间。
- 键帽保持真实错列与长键比例。正面上方显示普通层，下方显示左 Fn，底部侧面显示右 Fn；编号按需显示在右侧，已修改圆点位于左侧底部。
- 只高亮当前键帽及选中映射，不联动整层。计数视图用次数替代底部右 Fn，导航跳过隐藏的层；进入计数视图前若选中右 Fn，则回到同键普通层并保留草稿。
- 键帽、预览与图例固定使用英文短名称、缩写和符号；编辑选项显示本地化全名及必要缩写。完整名称与缩写都可搜索，不因长度将名称替换成键码。
- `src/lib/keycap-text.ts` 使用 Pretext 测量实际字体并缓存结果。布局与预览优先缩小字号保持单行，目前下限为 5px，仍放不下才换行；完整名称保留在悬停与编辑器中。
- 桌面右侧编辑栏固定在顶栏与底栏之间，摘要常驻，内容独立滚动；切换键位时内容回到顶部。900px 及以下使用编辑抽屉，关闭后焦点回到当前键位。
- 待写入改动使用独立左侧栏，列出完整差异及未应用输入。1600px 以下默认收起并以抽屉打开；1600px 及以上默认展示三栏。收起后释放空间，工具栏保留入口及数量。
- 键盘按可用宽度缩放，1280 × 800 起布局无需横向滚动；900px 以下保留横向滚动以保证键位可操作。调整后需重新核对实际布局，不能仅凭断点推断通过验收。

## 国际化

资源位于 `src/i18n/zh-CN.ts`、`src/i18n/en.ts`；按键全名在 `key-names.ts`，键帽标签在 `key-labels.ts`。类型与测试检查键和插值参数一致。

语言选择优先使用当前来源的保存值，其次匹配浏览器偏好，最后回退到简体中文。存储不可用时仍可在当前页面切换。

状态与日志保存消息标识，因此已有记录也可切换语言。语言切换保留草稿、选键、配置与连接，不改变 JSON、`.pro` 或历史备份内容。所有翻译随产物内联。

## 页面工具

支持 WebMCP 的宿主可选注册三个工具：查询状态、读取已载入按键配置、批量暂存改键。它们没有 USB 授权或硬件写入能力；`atom66_read_keys` 读取编辑器中的配置，不向键盘发起读取。

工具名称保留兼容前缀，但返回当前编辑器型号、键数及层名。型号切换时重新注册输入范围。暂存同样受未应用输入和操作锁约束，最终写入必须由用户在页面确认。

## 构建与验证边界

`scripts/standalone.ts` 将脚本与样式内联，按实际脚本计算 SHA-256 CSP，并将经典脚本放在挂载节点之后。生产 CSP 保留 `connect-src 'none'`，开发环境使用独立配置以允许 Vite 热更新。

产物为 `dist/index.html` 与 `dist/_headers`，无 CDN 或外部图片依赖。保留 `base: './'` 和仅发布 `dist/` 的边界；构建及 Pages 工作流见[贡献指南](../CONTRIBUTING.zh-CN.md#构建与静态部署)。

FakeHID 验证协议与命令顺序，jsdom 验证 DOM 交互及产物启动；两者都不能证明真实 USB、浏览器权限、CSP 执行或 IndexedDB 持久化正常。私人样本回放只证明样本范围内的解析和报文往返。
