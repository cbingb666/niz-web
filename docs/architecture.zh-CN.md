# 架构与兼容性

[English](architecture.md) · **简体中文**

[返回贡献指南](../CONTRIBUTING.zh-CN.md) · [Agent 工作约定](../AGENTS.md)

NIZ Web 是纯浏览器应用，通过 WebHID 访问键盘的 USB 配置接口。没有本地设备代理、后端服务或云端配置存储。当前协议实现来自原版 DLL、已有原生移植及真实读取样本；ATOM66 的配置使用已实机验证（用户反馈）；ATOM68、MICRO82、MICRO84、校准效果和固件刷写仍待实机验证。

## 型号识别与配置归属

`src/devices/atom66/`、`atom68/`、`micro82/` 和 `micro84/` 中的 `model.ts` 集中维护 USB 筛选条件、固件识别、物理布局、编辑层、配置组数、Fn 规则、计数 / RGB 能力及演示内容。

`src/devices/model.ts` 定义接口，并从布局和层数推导键数与可编辑记录范围。物理键可通过 `gapBefore` 指定键宽单位的前置留白，渲染与纵向方向键导航均计入这些间隔。`src/devices/index.ts` 是生产型号的唯一注册入口，目前注册 ATOM66、ATOM68、MICRO82 和 MICRO84，后三款尚未实机验证。

连接时先筛选 USB 配置接口，再读取固件，在候选型号中唯一匹配。未知或匹配多个型号时，不继续读取按键配置。同一个 USB ID 不代表同一型号，也不能按报文数量猜测型号。

ATOM66 的 USB 筛选包含 `0483:502A/512A/522A/542A`。`542A` RGB 接口出现在原厂 2023 年 6 月 ATOM66 编程资料包中，本轮也在连接的 `66EC-RGB` 上观测到。它仍须具备 `0x8C/1` 配置 collection、Report ID `0` 的 64 字节输入和输出报告，并匹配 `66EC` 固件。详见[验证记录](../VALIDATION.md#2026-10-04atom66-rgb-usb-筛选补齐)。

`HIDSession` 保存设备型号，`Profile` 保存配置型号。编辑器、布局、方向键导航、确认摘要和页面工具均使用配置的型号信息；未载入配置时默认显示 ATOM66。

两个离线演示入口复用 `src/components/demo-launcher.tsx` 打开 `demo` 过渡页。`src/components/demo-picker.tsx` 使用本地产品图和原生单选框展示生产注册表中的型号，并提供统一的「开始演示」操作。型号选择与返回入口独立于编辑器，所选型号在页面与语言切换后保持。前往过渡页时连接引导保持挂载并隐藏，返回后保留步骤和输入。开始演示时沿用已有替换确认再载入所选型号；取消保留配置和草稿。编辑器、编辑世代或连接变化会使待完成的替换确认失效。选择和载入演示不发送硬件命令。

导入合并、配置比较和硬件写入均检查型号一致性。即使固件字符串和记录数量相同，也不能混用不同型号的配置。

### 扩展型号

1. 从官方资料与真实只读样本确认 USB 标识、固件识别、按键顺序、布局、配置组数和能力。
2. 确认共用 NIZ EC 报文及命令格式后，在 `src/devices/<型号>/model.ts` 定义型号，并加入 `supportedModels`。计数与 RGB 长度、记录寻址、编辑范围和 Fn 同步应从型号定义取得。
3. 如果命令、报文结构或键码含义不同，先实现协议与转换，再扩展协议选择。`protocol: 'niz-ec'` 只声明已实现的协议，添加参数不等于支持新协议。
4. 增加真实样本的报文往返与设备行为验证，再声明支持。

`tests/model-fixtures.ts` 中的 68 键 / 2 层 / 4 组型号是未注册的虚构测试设备，只用于检查结构可扩展性。

## 兼容格式

| 内容 | 保留的格式或标识 |
| --- | --- |
| ATOM66 JSON | `format: 'atom66-macos'`；旧导入文件与备份明确归属 ATOM66 |
| 新型号 JSON | `format: 'niz-web'`、`schema: 1`，必填 `model` 型号 ID |
| ATOM66 读取诊断 | `atom66-read-capture` |
| 新型号读取诊断 | `niz-read-capture`，携带 `model` |
| 浏览器备份数据库 | `atom66-web-backups` |
| 语言偏好 | `atom66.locale` |
| 页面工具 | `atom66_read_status`、`atom66_read_keys`、`atom66_stage_key_edits` |

`src/devices/legacy.ts` 根据各型号明确识别的根标签和键位数量转换 Windows `.pro`，保留原有 `src/devices/atom66/legacy.ts` 导入路径。JSON 和备份导入检查型号归属，同版本导入保留原有完整配置合并行为。

`src/protocol.ts` 的 `prepareImported` 支持同一已注册型号的不同固件版本迁移，不设置版本白名单。它克隆当前读取基线，仅解码并重新编码可编辑层的定义；保留目标版本、设备信息、计数、旧格式附件和全部隐藏扩展字节，源与目标组数不同也可迁移。仅当两份配置都声明支持逐键 RGB 时迁移灯光。Mac 功能同时检查源和目标版本的可用性，避免把旧保留码解释为新功能；不支持或无法重新编码的映射保留目标记录。跳过含 Fn 分配的键位时同步保留其联动层，最终配置必须通过 Fn 和写入结构校验。返回结果包含未迁移键位与原因，供 store 显示双语提示并记录日志。离线导入没有目标，保留原版本。文件与备份异步加载检查发起时的编辑器、编辑世代和连接世代。硬件写入仍要求当前读取基线与精确目标固件一致，完成外部改动检查、备份事务和回读验证。

ATOM66 支持完整三组或九组配置。V1.4.4 九组共 594 条记录，界面只编辑前三组；其余六组保留原始报文，写后校验逐字节比较扩展组。三组文件合并到已读取的九组配置时，使用设备原有扩展组，不将其清空。

ATOM68 为 68 键、三个可编辑层。原厂客户端读写六组配置（408 条记录），`.pro` 同样保存六组。后三组保留原始报文，三组 JSON 合并到已读取的六组配置时保留设备原有扩展组。型号识别排除使用独立 USB 接口的 ATOM68 Pro。详见[官方软件核对与待实机验证项（英文）](atom68-research.md)。

MICRO82 / MICRO84 分别为 82 / 84 键、三个可编辑层；本次核对的原厂客户端与 `.pro` 文件为三组，共 246 / 252 条记录。六行布局保留独立功能键行；MICRO82 使用长空格，MICRO84 使用左 Fn、短空格、右 Fn 和 Menu。两者独立检查 USB、固件、JSON 归属与 `.pro` 根标签，未知组数会被拒绝。本次不包含 MICRO82 Pro、MINI84 或其他 84 键系列，也不开放两款 MICRO 的校准。详见[官方软件核对与待实机验证项（英文）](micro-research.md)。

## 设备、编辑与写入

`HIDSession` 由应用入口管理生命周期，React StrictMode 不会重新创建连接。Zustand 通过设备事件同步视图，组件切换不会触发硬件写入。

连接通道、型号、读取基线与连接世代按设备隔离。每台设备也有独立的编辑器、草稿、选键及撤销历史。新增连接不会切换工作台，旧确认不能用于新连接。

连接只识别设备。用户从「配置设备」或「重新读取配置」发起读取并确认后，才读取配置。取消或失败不会自动重复读取。

配置写入流程依次为：校验配置归属与基线、再读设备检查外部改动、完成备份事务、发送配置、回读比较。一次用户确认覆盖整个流程。写入不是设备级原子事务，中断可能造成部分写入，不自动重试或回滚。

`BackupStore` 比较型号、固件、保存的设备信息、全部原始键位报文、灯光和旧版附件。设备信息的属性顺序、十六进制字母大小写、备份时间、来源和按键计数不构成新配置版本。查找与 `put` 在同一笔 IndexedDB 读写事务内完成，复用最近的匹配 ID，并更新快照、时间和来源；传入快照没有计数时（如配置写入前检查），从匹配备份中保留最近可用的计数。复用时仍须等待事务完成，失败仍阻止硬件写入。数据库保留 `atom66-web-backups` 名称及版本 1。列表按相同规则合并旧重复记录，只返回最近的快照；旧存储记录和 ID 保留，仍可用于下载及页面内固件结果。

编辑模型保留最多 50 笔已应用操作，包含 Fn 联动、批量改键与 RGB。载入新配置或写入成功后清空历史；未应用输入按层和键位保留，不进入已应用操作的历史。

### 进度语义

| 阶段 | 进度依据 |
| --- | --- |
| 发送按键配置 | 成功发送包数 / 本次总包数，包含宏续包 |
| RGB 与按键计数 | 实际收发字节数 / 当前型号所需字节数 |
| 回读 | 已接收包数 / 待校验配置包数；超出目标数量时不再显示比例 |
| 初次读取与写前检查 | 未知总包数，只显示阶段状态与等待指示 |
| 本地备份、设备处理等待、结果校验 | 无传输比例，只显示阶段状态与等待指示 |

实际收发量由底层进度事件记录，界面不显示步骤编号或数据包明细。发送阻塞或失败时完成量不增长；页面锁定持续到整笔事务成功或失败。

## 校准

[校准功能](../CONTRIBUTING.zh-CN.md#校准开发)对 ATOM66 型号定义中的精确组合默认开放，开发环境和生产构建一致。可用性只有 `available` 与 `unsupported`，依据型号归属、VID/PID、固件和描述符判断，不依赖构建模式或环境开关。型号元数据另行保留候选/已验证的证据状态，当前两个组合仍是候选；默认开放不代表通过硬件验证。`HIDSession` 在准备确认目标和实际开始时都会重新检查组合与描述符。

`calibration.ts` 负责释放/按下时序、预期 `DA`/`DE`、等待用户和结果类型。`HIDSession` 捕获具体连接记录而不选择其编辑器，并从开始到结束或失败保持一个独占操作。按下/结束动作向该运行传递信号，不嵌套排队 exclusive；校准期间新配置操作直接拒绝。确认标识只使用一次，绑定设备对象和连接世代。不在连接时自动校准，不自动重读、重试或回滚。

`PacketChannel` 单独跟踪实际发送 Promise 与超时时限。私有权限仅允许在原设备仍打开、前序发送均已结束时执行一次最终解锁，包括接收/协议失败后；不恢复失败通道，也不开放任意清理命令。失败或不确定时只停用目标连接并暂停自动恢复，其他设备的连接与编辑保留。正常停止应用会中止等待用户并在关闭句柄前尝试符合条件的有界清理；强制关闭不能保证清理。

校准在会改变数据的命令之前使目标硬件写入基线失效，保留本地编辑状态，快照和每设备结果独立于 `Profile`。可选 `niz-calibration-capture` 最多记录 256 条观测并标记截断，区分发送尝试/成功/拒绝/超时及输入，保留完整观测字节，不包含试键文字，由用户主动下载，不改变既有配置格式或备份。当前 10 秒回复时限属于实验参数，不是实测固件耗时。

校准向导复用基础 UI，背景 inert 时只允许当前阶段动作。终止错误解除页面操作锁，并且即使没有载入配置也可回看。WebMCP 不提供校准动作。硬件资格验证仍待完成，详见[调研](calibration-research.zh-CN.md)和[落地方案](calibration-implementation-plan.zh-CN.md)。

## 固件刷写

`firmware.ts` 接受两个精确包：177,576 字节的原厂 V1.5.1，以及 179,378 字节的 Mac V1.5.1-F.1 实验构建。`stockFirmware` 与 `macNativeFirmware` 分别固定 SHA-256、记录总数和目标版本。映射、软件验证和实机限制见 [Mac 原生固件](../niz-firmware/firmware/MAC_NATIVE.zh-CN.md)。哈希固定所有加密记录的内容，解析器另核对分隔、长度及白名单记录总数（原厂 3,352，Mac 3,386）。已验证包的报文保存在私有存储中，按需复制；构造元数据对象不能伪造包。运行时不导入固件二进制或研究源码。

`HIDSession` 独立要求型号 `atom66`、VID/PID `0483:542A`、当前完整版本 `66EC(RGB)BLe;V1.5.1;V1.0;` 或 `66EC(RGB)BLe;V1.5.1-F.1;V1.0;` 及匹配的输入/输出描述符，不从普通 ATOM66 配置支持继承刷写资格。确认目标为绑定原设备对象和连接世代的单次令牌，不要求提前载入配置基线。点击「开始写入」后，事务依次重新核对版本、自动读取完整键位、灯光与按键计数、对本次刚读到的状态完成持久化备份、使目标既有基线失效，再串行发送 Report ID 0 / 64 字节 `0x3A` 报文；读取或备份失败必须停止传输。新读取快照只用于备份，不替换已载入的编辑器、草稿和历史；store 阻止目标设备的未应用输入。配置写入继续保留自己的基线及外部变化检查。

接收器只有 `00 3A A0/A1` 错误回复，没有明确的刷写成功回复。异常回复和传输错误会停止后续发送，不重试、回滚或复用校准解锁清理；实际发送超时且尚未结束时，不并发清理命令或关闭。自动恢复排除已退役的原设备对象。进度只统计成功发送的记录，EOF 后切换为未知时长的重启等待。25 毫秒包间隔保守参考反编译中的 8 毫秒 EEPROM 页写入延迟及跨页情况；它和 15 秒重启观察时限都是临时边界，不是实测保证。

观察到断开后，版本核对通过用户明确触发的受限设备选择器执行，只查询 `F9`，拒绝刷写前已连接的其他设备，不重发固件。新枚举对象不能根据型号/版本可靠配对，因此由用户选择实体键盘，结果明确为「所选设备版本已核对」，不是逐字节固件验证。同版重刷也必须观察到断开，否则结果保持不确定；迟到的断开可开放核对。结果和备份 ID 留在页面内供复查；WebMCP 不提供刷写操作。

静态依据为中文研究仓库中的 `niz-firmware/recovered/PROTOCOL.md` 和 `niz-firmware/firmware/mac_updater_compatibility.json`。尚未进行真实 USB 刷写、引导程序 APROM 写回、断电资格验证或恢复验收。详见[使用流程](usage.zh-CN.md#固件刷写)和[验证记录](../VALIDATION.md)。

## 界面实现

`routing.ts` 在应用入口、渲染之前将浏览器历史与 store 绑定。Hash 路由保留原有路径和查询参数，无需静态托管回退。演示型号选择替换当前历史项，页面切换与进入指定型号的离线编辑器增加历史项。型号来自生产注册表；没有载入数据的硬件编辑器链接返回设备管理。历史导航复用 store 的离开/替换确认，取消或锁定时恢复原历史位置，不授权 USB，也不读取设备配置。路由自身的历史状态仅记录序号，不记录编辑数据。对于拒绝 History API URL 参数的不透明文件来源，只修改地址片段，再以不含 URL 的调用标记历史项。监听器和订阅随应用清理，生命周期独立于 React 渲染。

- 主题令牌位于 `src/styles.css`，`components.json` 配置 `@/` 别名。弹窗复用现有 Dialog / AlertDialog 的尺寸、圆角、间距和按钮。
- 设备管理、连接引导与工作台共用设备命名：优先设备名称，仅重名时附加本页面编号。编号不作为跨页面身份。
- 设备卡片从「断开」左侧的信息图标打开共用的「设备详情」弹窗。弹窗指向所点设备，不切换编辑器或发送命令。关闭后焦点返回入口；所查看的设备断开时，弹窗关闭，焦点回到页面标题。
- 设备卡片与编辑器中的「断开」均为图标按钮，共用确认弹窗，显示目标设备名称并默认聚焦「取消」。确认绑定设备 ID 与连接世代，撤销授权前和断开操作进入队列后都会复核；连接变化使旧确认失效。取消保持连接，确认或取消均保留本地编辑及其他设备。
- 顶栏提供品牌、面包屑、手册、语言、帮助与 GitHub 链接。「键盘手册」复用共享弹窗，提供型号选择；选择仅属于弹窗，不切换设备，也不发送硬件命令。`src/lib/manuals.ts` 记录来自 `drivers/manuals-2023-06.json` 的原始文件链接，构建只内联链接。关闭后焦点回到顶栏入口。底栏左侧集中设备、备份和操作记录工具，右侧依次放置撤销、重做、可见的导入/导出按钮和写入，不显示修改摘要、状态文本或恢复提示。窄屏保持各操作组完整，文件按钮继续右对齐。页面按底栏实际高度预留空间。
- 键盘主区域突出选键和配置来源，去掉重复的型号、返回按钮与协议记录数。离线编辑从底栏进入连接引导；导入、导出和还原保留可见文字标签。草稿继续显示在编辑器和改动列表中；操作失败沿用错误弹窗，错误详情保留在操作记录中。状态与日志的消息标识不变。
- 键帽保持真实错列与长键比例。正面上方显示普通层，下方显示左 Fn，底部侧面显示右 Fn；编号按需显示在右侧，已修改圆点位于左侧底部。
- 只高亮当前键帽及选中映射，不联动整层。计数视图用次数替代底部右 Fn，导航跳过隐藏的层；进入计数视图前若选中右 Fn，则回到同键普通层并保留草稿。
- 键帽、预览与图例固定使用英文短名称、缩写和符号；编辑选项显示本地化全名及必要缩写。完整名称与缩写都可搜索，不因长度将名称替换成键码。
- 各层的空映射与原厂功能码 `0` 统一显示为「未设置」，键帽符号统一为「—」。显示时保留两者不同的报文编码；选择「未设置」仍分配功能码 `0`。历史输入名称「无功能」和 “No action” 继续可用。
- `src/lib/keycap-text.ts` 使用 Pretext 测量实际字体并缓存结果。布局与预览优先缩小字号保持单行，目前下限为 5px，仍放不下才换行；完整名称保留在悬停与编辑器中。
- 桌面右侧编辑栏固定在顶栏与底栏之间，摘要分开展示键位、层和当前功能，并显示未应用或暂存状态。内容独立滚动；摘要过长时也可独立滚动，不占满编辑栏。切换键位时内容回到顶部。900px 及以下使用编辑抽屉，关闭后焦点回到当前键位。
- 编辑栏底部保留应用、放弃按钮和编辑错误，不随内容滚动。搜索覆盖全部分类，清除后恢复原筛选；功能按钮只占一个 Tab 停靠点，可用方向键浏览。快速选键不能替换未应用草稿；无法编辑当前草稿的快捷键视图会禁用编辑，并提供「继续编辑」。快捷键录入允许 Tab 离开，Esc 只取消录入，不关闭抽屉。
- 待写入改动在所有屏幕宽度下统一使用一个居中弹窗，打开时聚焦标题。改动按层分组，用实体键帽名称和编号定位，并标注修改前后。宏延时和播放设置直接显示，序列在原弹窗内展开。未应用输入优先展示，提供明确的继续编辑操作。「编辑」返回对应映射，窄屏同时打开编辑抽屉。可写入时进入原有锁键确认，确认前不发送配置命令。列表滚动时标题和底部操作保持可见，写入确认中仍可查看完整差异。
- 键盘按可用宽度缩放，1280 × 800 起布局无需横向滚动；900px 以下保留横向滚动以保证键位可操作。调整后需重新核对实际布局，不能仅凭断点推断通过验收。

## 国际化

资源位于 `src/i18n/zh-CN.ts`、`src/i18n/en.ts`；按键全名在 `key-names.ts`，键帽标签在 `key-labels.ts`。类型与测试检查键和插值参数一致。

语言选择优先使用当前来源的保存值，其次匹配浏览器偏好，最后回退到简体中文。存储不可用时仍可在当前页面切换。

状态与日志保存消息标识，因此已有记录也可切换语言。语言切换保留草稿、选键、配置与连接，不改变 JSON、`.pro` 或历史备份内容。所有翻译随产物内联。

## 页面工具

支持 WebMCP 的宿主可选注册三个工具：查询状态、读取已载入按键配置、批量暂存改键。它们没有 USB 授权或硬件写入能力；`atom66_read_keys` 读取编辑器中的配置，不向键盘发起读取。

工具名称保留兼容前缀，但返回当前编辑器型号、键数及层名。型号切换时重新注册输入范围。暂存同样受未应用输入和操作锁约束，最终写入必须由用户在页面确认。

## 构建与验证边界

`scripts/standalone.ts` 将脚本与样式内联，按实际脚本计算 SHA-256 CSP，并将经典脚本放在挂载节点之后。Vite 将 `src/assets/favicon.ico` 以内联 data URL 嵌入 HTML。生产 CSP 保留 `connect-src 'none'`，开发环境使用独立配置以允许 Vite 热更新。

产物为 `dist/index.html` 与 `dist/_headers`，无 CDN 或外部图片依赖。保留 `base: './'` 和仅发布 `dist/` 的边界；构建及 Pages 工作流见[贡献指南](../CONTRIBUTING.zh-CN.md#构建与静态部署)。

FakeHID 验证协议与命令顺序，jsdom 验证 DOM 交互及产物启动；两者都不能证明真实 USB、浏览器权限、CSP 执行或 IndexedDB 持久化正常。私人样本回放只证明样本范围内的解析和报文往返。
